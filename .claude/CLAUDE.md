# create-pr

Bash tool that automates PR/MR creation for GitHub (`gh`) and GitLab (`glab`).
Extracts ticket info from branch names, generates titles/bodies/labels from templates.

## Project structure

- `create-pr` — entry point script (version declared as `CREATE_PR_VERSION`)
- `src/*.sh` — source modules, each with namespaced functions (`pr_title::`, `helpers::`, etc.)
- `tests/unit/*_test.sh` — unit tests (bashunit)
- `tests/e2e/*_test.sh` — end-to-end tests (bashunit)
- `lib/bashunit` — test runner
- `bin/create-pr` — built single-file executable (generated by `build.sh`)
- `.env` — local config template
- `Makefile` — dev commands (test, sa, lint, pre_commit)

## Tech stack

- **Language:** Bash (strict mode: `set -euo pipefail`)
- **Testing:** bashunit v0.26.0
- **Static analysis:** ShellCheck
- **Linting:** editorconfig-checker
- **Dependencies:** bashdep
- **CI:** GitHub Actions (tests on Ubuntu + macOS, ShellCheck, editorconfig)

## Coding conventions

- Follow the [Google Shell Style Guide](https://google.github.io/styleguide/shellguide.html)
- Namespace functions with their filename prefix: `pr_title::`, `helpers::`, `main::`, `validate::`, etc.
- Use `snake_case` for variables and functions
- Always use `local` for function-scoped variables
- Use `set -euo pipefail` in scripts
- Suppress specific ShellCheck warnings with inline `# shellcheck disable=SCXXXX` comments only when justified
- Keep each source file single-responsibility

## Commands

- `make test` — run all tests
- `make sa` — run ShellCheck static analysis
- `make lint` — run editorconfig-checker
- `make pre_commit/run` — run test + sa + lint (what pre-commit does)
- `./build.sh` — build single executable into `bin/create-pr`
- `lib/bashunit tests` — run tests directly
- `shellcheck ./**/*.sh -C` — run ShellCheck directly

## Testing guidelines

- Test files mirror source files: `src/foo.sh` → `tests/unit/foo_test.sh`
- Test functions are named `test_<description>` (no `function` keyword required by bashunit, but this project uses it)
- Use `set_up()` for per-test setup (export env vars, source files)
- Use `assert_same`, `assert_equals`, `assert_exit_code`, etc. from bashunit
- Use data providers: `# data_provider provider_name` comment above the test function
- Snapshot tests live in `tests/unit/snapshots/`

## Release process

1. Update `CREATE_PR_VERSION` in `create-pr`
2. Update `CHANGELOG.md`
3. Run `./build.sh` to generate `bin/create-pr` and `bin/checksum`
4. Create GitHub release, attach `bin/create-pr` and `bin/checksum`

## Commit conventions

- Use conventional commits: `feat:`, `fix:`, `docs:`, `ref:`, `test:`, `chore:`, `release:`
- Use `ref:` (not `refactor:`) for refactoring commits
- Never add Co-Authored-By or any trailer referencing Claude/Anthropic
